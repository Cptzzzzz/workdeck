# 主节点主动升级 Agent 的设计方案

## 目标与边界

管理员从节点管理页选择目标节点和已发布版本，由主服务逐台发起升级并跟踪结果。升级只更换 Agent 与必要的文件工作进程，不终止独立的终端会话；浏览器连接可能短暂中断并重连。操作系统重启、用户主动终止会话仍有各自的既有行为。方案尚未实现，当前版本仍使用安装脚本或管理员授权的临时终端升级。

## 协议与权限

- 仅允许已登录的管理员通过带 CSRF 防护的接口创建升级任务；Agent 通过现有双向认证控制连接接收绑定节点身份、目标版本和任务 ID 的升级命令。
- 版本必须从主服务已批准的发布清单选择，禁止提交任意命令、URL、路径或 shell 参数。旧节点不支持升级能力时明确显示“需先手动升级”，不得假装已发起。
- 每节点只允许一个任务；任务有过期时间、幂等 ID、审计记录及独立状态，离线、权限不足、校验失败和兼容性不匹配须分别显示。

## 下载、校验与切换

1. Agent 检查自身架构、运行账户、服务作用域、剩余空间、目标版本与协议兼容性，下载到服务账户可控的私有临时目录；不暴露密钥或终端内容。
2. 校验版本、架构、大小和摘要。仅依赖同一下载服务器上的 SHA-256 只能检查传输差错；正式发布宜增加独立签名，并由节点使用预先固定的发布公钥验证，拒绝未签名或签名错误的包。
3. 对新二进制执行只读版本自检，在同一文件系统使用临时文件和原子重命名替换，并保留旧版本及其权限。root Agent 涉及文件工作进程时同步校验、备份和替换，普通用户 Agent 只修改其用户目录。
4. 使用短生命周期、独立于 Agent 的用户级或系统级 systemd 辅助服务执行重启与看门狗；辅助服务不得停止终端的独立服务单元。新 Agent 需在限定时间内重新认证、报告目标版本和完整清单。
5. 若验证、替换、重启或上线确认失败，辅助服务回滚旧二进制并再次启动；若回滚失败，保留诊断及恢复命令。Hub 重启或网络中断后，节点和主服务通过持久化任务 ID 重新核对，避免盲目重复执行。

## 体验与验收

界面显示预检、下载、校验、重启、重连、成功或回滚等阶段；支持多节点逐台执行、失败时暂停，禁止对已离线节点声称升级成功。验收需覆盖普通用户和 root Agent、旧版本兼容、异常中断、损坏包、网络分区、Hub 和节点重启、回滚，以及在升级前后核对现有 tmux 和终端进程身份。所有升级状态与日志不得包含令牌、私钥、终端输入或输出。
