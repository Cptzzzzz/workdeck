# 飞书任务通知

Workdeck 可以通过飞书企业自建应用机器人，向一个用户私聊或群聊发送 Codex 任务提醒。主服务在后台发送消息，浏览器关闭后仍然生效；该功能只发送通知，暂不接收飞书回复。

## 在飞书准备应用

1. 打开[飞书开放平台](https://open.feishu.cn/)，在自己的企业或团队中创建企业自建应用。
2. 给应用添加**机器人**能力，申请“以应用的身份发消息”（`im:message:send_as_bot`）权限。创建应用版本并完成发布，确保接收人属于应用的可用范围。
3. 在应用的“凭证与基础信息”中获取 App ID 和 App Secret。App Secret 是密码，请直接填写到 Workdeck 设置中，不要提交到仓库或发送到群聊。
4. 确定接收目标：私聊使用**当前应用对应的用户 Open ID**；群聊使用 Chat ID，并先将应用机器人添加到群里。不同应用的同一个用户 Open ID 不同。

获取 Open ID 的一种官方方式是在应用中申请“通过手机号或邮箱获取用户 ID”（`contact:user.id:readonly`），发布后通过[飞书 API 调试台](https://open.feishu.cn/api-explorer)调用“通过手机号或邮箱获取用户 ID”，选择 `open_id` 类型并查询自己的账号；也可以使用组织现有的合法 ID 获取方式。所需权限或发布可能需要组织管理员审核。参见[飞书机器人说明](https://open.feishu.cn/document/client-docs/bot-v3/bot-overview)和[获取 Open ID 的示例说明](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)。

## 在 Workdeck 配置

1. 在终端模式左下角或工作区模式左下角打开**设置**，找到**飞书通知**。
2. 填写 App ID、App Secret，选择用户私聊或群聊并填写对应 ID。选择需要的完成和待处理事件，然后开启并保存。
3. 点击**发送测试通知**。收到测试消息后，实际任务状态变化就会自动通知。

设置保存在主服务，多个浏览器共享。App Secret 只在保存时提交，不会再次返回或写入浏览器持久存储；数据库中的密钥经过加密。保存新的设置会取消旧配置下尚未发送的消息，避免消息发送给已经更换的接收人。首次启用不补发启用以前的历史状态。

## 事件和可靠性

- 受管 Codex 的根 Goal 为 `active` 时，不会把子任务或普通轮次结束发送为 Goal 完成。Goal 的 `complete` 会通知目标完成；没有 Goal，或当前轮次开始于旧 Goal 完成之后时，通知本轮结束。暂停、受阻、预算/用量限制、中断和等待输入等可以作为需要处理通知。
- 普通终端通过受信任的 Codex Hook 跟踪时，Stop 事件只能提示**可能已结束**；它无法可靠判断 Goal 是否完成。节点上的旧版受管会话仍可由新 Agent 通过其私有 App Server 只读补充时间信息，不必重启现有会话；如果无法可靠获取时间，状态显示未知并暂不发送未经核实的 Goal 完成通知。
- 节点把观察到的关键状态变化先存到本地私有队列，得到主服务确认后删除。Hub 将事件写入持久化队列，按事件身份去重；网络或飞书调用失败时自动重试，Hub 重启后继续发送。普通轮次结束会短暂等待并核对当前状态，避免已经继续工作的旧提示。
- 通知内容只有任务名称、节点名称、状态、北京时间和指向对应终端的 Workdeck 链接，不包含终端输出、项目文件、完整对话或代理。链接需要正常登录 Workdeck。
- 状态检测本身有采样和旧版 Hook 的限制。旧版受管会话如果在 Agent 停止期间经历多次状态变化，Agent 恢复时只能看到最后的状态；新创建的受管会话会在观察器侧持久化关键事件。网络请求在飞书已接收但响应丢失时会按相同消息 UUID 重试，仍取决于飞书的去重期限。

## 运维

主服务数据目录中的 `feishu.key` 是用于解密 App Secret 的密钥；迁移或备份时必须与 `workdeck.db` 一起安全保存。节点的 `codex-notification-outbox` 和 `codex-notification-baselines` 存于该节点的 Workdeck 私有数据目录，也应随节点身份备份。不要把这些文件或数据库提交到公开仓库。

若测试失败，检查应用是否已发布、机器人是否启用、发送权限与可用范围是否正确、接收 ID 是否属于当前应用、群聊是否已添加机器人，以及主服务器是否能访问飞书。设置页会显示待发送数量和不包含凭据的错误代码；网络恢复后自动重试。
