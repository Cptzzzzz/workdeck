# Tailscale 联动设计与进度

目标是保留公网访问和现有 WebSocket / WebRTC 自动回退，在用户设备和节点可经同一 Tailnet 通信时优先评估绕开 Hub 的数据路径。该功能尚未完整实现；本阶段仅增加 WebRTC 已选候选地址的本地提示，不证明 Tailscale 身份或物理直连，也不改变路由选择。

## 已验证与限制

- 在一个 Linux Agent 上，用项目相同的 Pion UDP 配置，离线采集候选时确认包含本机 Tailscale 接口的两个地址。浏览器是否采集和选择该接口仍需在目标设备验证。
- 浏览器的候选地址可能由 mDNS 隐藏或根本不提供；`100.64.0.0/10` 也可用于其他网络。界面只能称为“可能使用”，缺失时显示未知，不存储或上传候选地址。
- Tailscale 网络可能通过直接 UDP、DERP 或 Peer Relay 承载；使用 Tailscale 地址并不证明底层直连或绕开 Hub 主机。
- 现有终端与文件已有 WebRTC 自动探测，可能选中 Tailscale 网卡；尚没有直接识别当前浏览器设备或 Tailscale WSS。

## 待实现：浏览器设备探测

Hub 提供可选的 Tailnet 专用 HTTPS/WSS 探测入口，通过可信接入层获取真实 Tailscale 来源并调用受限的本地 Tailscale 身份查询。浏览器现有登录会话获取短时、一次性随机挑战，经 Tailnet 入口完成探测并绑定到原登录会话；公网请求、自报地址及外部提交的身份头均不能作为证明。挑战需绑定来源、会话和有效期，防重放并在退出、撤权和失联时失效。Hub 的 Docker 隔离、可信代理和 Caddy 的部署需独立设计，不应将 Tailscale 管理 socket 或认证密钥暴露给浏览器或整个容器。

探测只说明设备能访问 Hub，不代表能访问每台节点。浏览器网络策略、TLS、CSP、私网访问权限可能导致探测失败，失败不可影响原有连接。需要明确的功能开关和诊断，不把失败视为用户未安装 Tailscale。

## 待实现：节点直连与授权

Agent 在明确启用后上报有界的候选端点和能力，节点与上报信息必须经过现有 Agent 身份绑定。若 WebRTC 不能稳定使用 Tailnet，增加仅向 Tailnet 开放的节点 HTTPS/WSS 入口，设计证书续期与配置冲突处理。Hub 签发短期、单次、绑定节点、终端或工作区及读写权限的授权；Agent 验证签名、过期、重放、当前控制权和撤销状态。不得将 Hub Cookie 或永久密钥交给节点，WebSocket Origin、CSP、并发授权、跨标签接管、断开和服务重启都需要覆盖。

现有 Hub 授权租约继续提供实时撤权；掉线时直连必须收敛到安全状态。文件写入保留操作 ID、版本和断线核对；终端保留独占控制、顺序边界、未确认输入不重放及 tmux 任务独立生命周期。

## 待实现：选择、界面和验收

分别探测 Hub 中转、现有 WebRTC 和 Tailscale WSS，并比较稳定性、终端 RTT、文件吞吐与 Hub 出站带宽；用迟滞和冷却控制切换。允许不可达节点、没有 Tailscale 的设备和旧 Agent 正常回退。界面区分 Workdeck 应用链路与 Tailscale 底层直连 / DERP / Peer Relay；缺少可信数据时标未知。

验收需使用 Mac 和 Windows 的真实浏览器、已加入和未加入 Tailnet 的设备、访问规则不允许的节点、不同 NAT / DERP、Hub 和 Agent 重启、目标失效、会话撤销、控制权接管、文件大传输及保存中断。不得只凭 tailscale ping 或 ICE 地址范围声称整个链路已直连。
