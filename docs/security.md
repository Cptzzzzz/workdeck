# 敏感信息清单与仓库脱敏规则

## 必须保密的凭证

| 信息                                | 常见位置                                                                                   | 泄露后的影响与处理                                                                                             |
| ----------------------------------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| 管理员初始密码、当前密码            | 本地 `.secrets/administrator.txt`、服务器 `secrets/admin_password`；当前密码的哈希在数据库 | 可登录工作台并访问终端。泄露后在界面修改密码；界面改密后初始化文件不再代表当前密码                             |
| 从节点私钥                          | `~/.local/share/workdeck/identity.json` 的 `private_key` 字段                              | 可冒充该节点。立即在工作台撤销节点身份，再重新生成身份接入；不能只换加入令牌                                   |
| 未完成接入时的私钥                  | Agent 数据目录中的 `enrollment.json`                                                       | 同样按节点身份凭证保护，不应分享整个接入目录                                                                   |
| 加入令牌                            | 工作台生成的接入命令、临时 token 文件、剪贴板及可能的 Shell 历史                           | 有效期 10 分钟，只能登记一个节点身份。同一密钥可在有效期内重试接入响应；令牌泄露应先检查是否出现陌生节点并撤销 |
| 浏览器登录 Cookie、CSRF 值          | 浏览器存储、HAR、调试日志                                                                  | Cookie 是有效登录凭证，CSRF 值也不应公开。退出登录可撤销对应登录；改密会撤销其他登录                           |
| SSH 私钥、GitHub 访问凭证、TLS 私钥 | 用户 SSH 目录、凭证管理器、Caddy 数据卷等                                                  | 不属于应用源码，不得上传仓库或 Docker 镜像                                                                     |
| Shell / Codex 的已有凭证            | 工作用户的配置目录、环境变量、项目 `.env`                                                  | 终端继承工作用户权限。持有终端访问权限即可接触该用户可读的数据，需独立保护这些凭证                             |

节点公钥、源码中的 `private_key` 字段名、示例 token 占位符不是私钥本身，不能只依赖关键词判断是否泄密。

## 应保持私有的数据

- **Hub 数据库与 WAL/SHM、备份**：包含密码哈希、登录与令牌哈希、节点公钥和终端元数据。哈希不是明文密码，但数据库仍不适合公开。
- **Agent 会话记录**：包含终端名称、工作目录、退出情况等。tmux 屏幕与历史在内存中，也可能显示密钥或工作内容。
- **终端截图、输出、日志、HAR、测试报告**：可能包含提示词、代码、文件路径、环境变量或认证信息。
- **真实服务器 IP、域名、SSH 用户、主机名、内网网段、Docker 网络名称、部署结构、本机路径、个人邮箱**：这些通常不是认证凭证，但会暴露个人信息和基础设施。公开仓库只使用示例值，真实部署参数放在 `.env.deploy.local`。
- **历史 Git 备份**：可能保留脱敏前的内容和提交邮箱，必须私有保存。发布前的备份存放在被忽略的 `.secrets/` 内。

## 当前仓库的处理方式

1. 凭证、数据库、构建产物、日志、测试截图和本地部署配置由 `.gitignore` 排除。
2. `.dockerignore` 采用允许列表，镜像只包含可执行文件、前端和 CA 根证书；CA 根证书不是 TLS 私钥。
3. 发布前检查全部提交历史，并清理真实基础设施信息和个人提交邮箱。仅删除当前文件无法清除历史内容。
4. 公开 `.env.deploy.example` 只提供占位配置；本地 `.env.deploy.local` 不上传。
5. 提交前执行 `git diff --cached` 并检查历史与待上传对象；不要用 `git add -f` 绕过忽略规则上传运行数据。

`.gitignore` 无法阻止强制添加文件，也无法清除已经提交的内容。若真实凭证曾被公开，应先撤销或轮换，再处理 Git 历史。

接入命令带有短期令牌，也应避免截图公开或写入共享笔记。Hub 负责身份认证、连接协商和前端代码分发，属于受信任组件。选中直连时，终端字节通过 WebRTC DTLS 在浏览器和 Agent 之间传输；中转时仍经过 Hub。此机制不承诺“对恶意 Hub 隐藏内容”的端到端信任模型。

WebRTC 的 ICE 地址与 SDP 包含网络拓扑信息，不应公开发布或写入共享诊断日志。默认外部 STUN 会看到地址发现请求的来源地址，不接收终端输入输出；可以替换 STUN 地址、清空外部 STUN 配置或禁用直连探测。直连仍依赖原有已认证 WebSocket 的存活，退出登录、撤销节点和控制权接管同样会撤销对应直连权限。
