# 终端首屏连接流程

点击未打开的终端时，浏览器挂载 xterm 并立即发起 WebSocket；已打开的标签直接切换已有视图。浏览器请求仍需通过主服务完成登录校验和写入权限分配。

## 节点预连接

支持预连接的主服务在控制通道下发配置。节点维护两条空闲、经过节点签名认证的 WebSocket。用户打开终端时，主服务优先分配空闲连接，通过原控制通道依次确定写入归属，并在预连接上绑定目标终端。节点确认绑定后附着到已有 tmux 会话，同时后台补充空闲连接。没有空闲连接、连接失效或节点版本不支持时，自动使用原有按需建连流程。

空闲连接只发送心跳，不附着终端，不读取或缓存后台终端输出。用户关闭页面只关闭查看连接，tmux 进程继续运行。节点控制通道断开时，其空闲和已分配连接一并清理，节点重连后重新准备。并发查看仍保持单个写入者；写入归属在控制通道中排序，避免不同预连接上的绑定顺序导致旧连接覆盖新连接的写入权限。

这消除了节点到主服务的新建 TCP/TLS/WebSocket 握手等待，但浏览器到主服务仍需要建立连接。预连接不能修复浏览器所在网络的公网连接问题。

## 首屏与链路优化

终端输出通过可用的 WebSocket 立即显示；WebRTC 在首次输出渲染后后台检测，检测成功再按链路策略切换。节点到主服务的连接沿用公网与可用 Tailnet 路径竞争，TLS 仍校验原主服务域名。

## 分段计时

主服务日志的 `terminal startup` 行关联一个随机 `trace`，记录收到浏览器请求、分配预连接或通知节点建连、节点数据连接到达、收到第一批终端输出等阶段。新版浏览器额外上报 WebSocket 打开、节点 ready、实际首屏渲染的耗时；等待超过五秒时上报一次尚未完成的阶段。

计时只包含随机关联标识、阶段和毫秒数，不记录终端内容、目录、地址或登录凭证。上报接口需要有效登录和 CSRF 校验，上报失败不阻塞终端。浏览器完成 TCP/TLS 握手之前的等待仅能由浏览器计时体现，不能用 Hub 收到请求之后的耗时代替。
