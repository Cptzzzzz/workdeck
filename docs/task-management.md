# 任务管理与 Codex 自动跟踪

会话管理支持备注、标签、重要标记和手动状态。信息由主服务保存，多个设备共享；自动观察不会修改手动状态，也不会启动、停止或重放终端任务。

## 直接启动受管 Codex

概览页中，“新建 Codex”与“新建终端”是两个独立入口。选择 **新建 Codex** 即可直接启动受管会话。执行用户仍是创建终端的节点服务账户；登录凭据、模型配置和项目权限均使用该账户的 Codex 配置。

- 创建表单直接设置任务名称、节点、工作目录、模型、推理强度、代理地址和“执行命令前确认”，不再选择执行预设。默认关闭“执行命令前确认”，即免确认执行并使用完整执行权限；手动开启时使用工作区写入并按需审批。
- 在节点页面或节点管理中点击“代理设置”，保存默认的 HTTP / HTTPS / SOCKS5 地址。新建 Codex 时自动填入所选节点的配置；切换节点会重新读取。可修改本次启动的地址而不覆盖节点默认值，留空则不使用代理。代理不会从 Shell 的 `coder` 函数中自动提取。
- 展开“恢复已有对话”，可按标题选择所选目录中的历史对话，并读取更早记录；也可手动填写 UUID。历史读取会覆盖 CLI、编辑器、执行任务和 App Server 等来源及不同模型服务，不会恢复或启动对话。为兼容 Codex 目录筛选遗漏已迁移对话的情况，节点先分页读取官方元数据，再按实际工作目录匹配，支持符号链接目录；不会改写对话文件或直接修改 Codex 数据库。
- 可指定模型、推理强度，或选择已有 Codex 对话进行恢复。节点需先安装兼容 Codex 并完成登录；已验证 `codex-cli 0.166.0`，需要 `--remote`、Unix app-server 和 Goal API。旧版或未安装时会提示原因，不会偷偷升级用户的 Codex。
- 所选工作目录会通过 `--cd` 显式传给 Codex：新会话使用此目录，`/resume` 默认按此目录筛选。填写 UUID 恢复时也继续使用所选目录，不会退回该会话以前记录的目录；不会迁移或改写历史对话。
- 受管后端与 TUI 位于终端自己的 systemd 单元中。关闭浏览器、切换模式以及重启 Hub / Agent 不会终止任务。退出 Codex 会回到同一个终端的 Shell；只有确认关闭终端时才停止整个终端单元。
- 操作系统重启后进程无法继续存活。节点和终端记录仍保留，界面不会把历史 Goal 误报为仍在运行；可在新终端中填写会话 UUID 恢复 Codex。会话管理中可查看该 UUID。

每个受管终端使用单独的本地 Unix Socket 后端，不向公网开放 Codex 接口。TUI 自己创建会话；只读观察器随后绑定根会话，每秒查询一次运行状态、最近轮次及官方 `thread/goal/get`。观察器不发送用户输入、不接管审批、不调用恢复接口，既有手工终端继续使用下文 Hooks 机制。

Goal 状态单独展示：执行中、完成、暂停、受阻、预算耗尽、用量受限。**根 Goal 为 active 时，即使某个轮次或子任务结束，也不会发整体完成通知；只有 complete 才显示 Goal 已完成。** 这表示 Codex 声明完成，不是 Workdeck 对结果正确性的独立验收。浏览器通知仍需在设置中开启；首次加载不补发历史通知，同一 Goal 的完成提醒会去重。

节点私有 `codex-launches/<终端ID>.json` 保存启动选项与会话绑定，文件权限 0600、目录 0700。本次启动的代理通过已认证控制连接发送至节点，不写入终端元数据、命令行参数或浏览器持久存储；确认关闭终端后删除该配置。节点默认代理加密保存在主服务 `node_codex_settings` 表中，密钥为数据目录下权限 0600 的 `node-proxy.key`。节点概览仅返回配置是否存在，地址只在已登录的设置和创建表单中按需读取。备份时应同时保护数据库与此密钥；主服务重启后可恢复默认代理。节点已有 Codex 对话内容仍按 Codex 自身规则保存在用户账户中。状态同步只传递状态、会话标识、Goal 用量与预算，不保存 Goal 目标文本或模型回复。恢复列表按需传递标题、ID、目录和更新时间；有标题时使用 Codex 保存的名称，没有时以简短预览作为标题，不读取完整轮次，也不将对话列表写入 Hub 数据库或浏览器持久存储。查询进程随取消或超时回收，不依赖终端进程。

参考：[Codex App Server](https://learn.chatgpt.com/docs/app-server)。

## 配置 Codex 跟踪

1. 在“节点管理”中，针对需要跟踪的节点选择“启用 Codex 跟踪”。节点会为 **Agent 所在的系统账户**合并用户级 `hooks.json`，保留其他 Hook；如果已有配置，修改前会在节点私有数据目录备份。自定义 `CODEX_HOME` 必须与 Agent 的设置一致。
2. 在该账户的 Workdeck 终端中启动 `codex`，运行 `/hooks`，审核并信任 Workdeck 的 Hook。Codex 对非托管 Hook 的信任检查不会被 Workdeck 绕过。各账户各节点分别配置和信任；非 Agent 账户的历史终端如果无法访问 Agent 的私有数据目录，暂时只能显示状态未知。
3. 信任后直接运行 `codex` 即可。已经运行的 Codex 是否加载新配置由 Codex 决定，不能保证动态接入；必要时在自然结束后退出并恢复会话，Workdeck 不会主动关闭它。节点管理可移除 Workdeck 的 Hook，保留其他配置；已启动的进程可能继续使用已加载配置。

## 状态与通知

终端标签、概览卡片和终端底栏显示最近的 Codex 状态；没有可信事件时不作推断。节点只读检查终端进程树中的进程名和父进程 ID，发现 Codex 时可提示“已检测到，状态未知”；进程检查不读取命令参数或终端内容，不能保证发现被隔离或脱离终端的进程。节点离线或终端不再运行时，历史状态显示为未知。节点将事件写入私有目录并主动上报，连接恢复时重新同步；浏览器通过事件流更新，轮询作为回退。浏览器通知默认关闭，需要在设置中授权；页面关闭、未登录或浏览器未运行时不推送。首次打开页面不补发历史通知。

“可能需要处理”对应权限请求等事件；其他 Hook 可能自动处理请求，因此用户应打开终端确认。停止事件意味着 Codex 到达一轮的停止环节；其他 Hook 可能要求继续，本轮结束不证明整个目标成功。完成通知会短暂等待并核对当前事件，但仍不能保证后续不会继续。节点只保存最近状态，极短时间内连续发生的事件可能合并，通知不是完整审计记录。中断、异常退出或 Hook 未获信任时，状态可能不完整或过期。不会通过解析屏幕文字猜测。

Workdeck 只保存事件类型、哈希标识和时间，不保存 Hook 输入中可能包含的提示词、模型回复、工具参数或对话记录。旧版节点和此前的启动命令仍可兼容，但普通 `codex` 自动跟踪需要新版 Agent。Codex 重启、节点重启、不同权限账户和多进程场景不能保证完整的事件追溯。

参考：[Codex Hooks 与信任审核](https://learn.chatgpt.com/docs/hooks)。
