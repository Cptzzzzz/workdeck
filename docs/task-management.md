# 任务管理与 Codex 轮次跟踪

会话管理中的“任务详情与 Codex 跟踪”支持备注、标签、重要标记和手动状态。信息由主服务保存，多个浏览器共享；手动状态不会改变终端进程，也不会被 Codex 事件自动覆盖。搜索会匹配标签和备注。

在需要跟踪的 Workdeck 终端中，复制并运行任务详情里的启动命令，再正常使用 Codex。命令可附加 Codex 参数。它只对本次启动设置 Codex 官方 `notify`，不修改用户配置；如果本来已经配置了 `notify`，本次启动的设置会覆盖它。旧终端可使用该命令启动新的 Codex，但已运行的 Codex 无法补接事件。终端账户必须有权访问节点数据目录；历史迁移产生的不同账户终端可能不满足此条件。

Codex 的 `agent-turn-complete` 只表示某一轮结束，不证明整个目标成功，也无法单独确定当前是否有新一轮正在执行、是否等待授权或是否发生错误。界面因此显示“最近一轮结束”和时间，不自动更改手动状态。未接入、节点离线、页面关闭或节点长期失联都可能导致观察不及时；计算机重启会结束本机进程，不能凭存储记录恢复任务。

节点只保存轮次标识的哈希和接收时间，不保存通知载荷中的提示词、模型回复或工作目录。事件随节点清单上报并持久化；短时间内多次结束只保留最近一次。浏览器通知默认关闭，需在设置中授权；页面关闭、未登录或浏览器未运行时不会收到推送。首次打开页面不补发历史通知，同一浏览器的多个标签页尽力去重。

参考：[Codex 通知配置](https://learn.chatgpt.com/docs/config-file/config-advanced)。
